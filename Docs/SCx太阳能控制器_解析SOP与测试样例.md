# SCx 太阳能控制器 RS485 解析 SOP 与测试样例

> 适用规则：`Assets/DeviceRules/SCx太阳能控制器.json`
> 适用程序：MultiSerialTool（WPF / .NET 9）
> 协议版本：《SCx 太阳能控制器 RS485 通信协议 V1.1》
> 目的：固定"组帧 → 校验 → 解析 → 落盘"全流程，保证每一次解析结果可复算、可追溯、不出错。

---

## 1. 帧结构（必须先背熟）

```
┌──────────────┬────────┬──────────────────────────────┬──────────┐
│ 帧头(6字节)  │ Length │ 用户数据区(UD)               │ 帧CheckSum│
│ 53 57 49 4F  │ 1字节  │ Command + UD Length + Data + │ 1字节    │
│ 54 54        │        │ 用户数据 CheckSum            │          │
│ "SWIOTT"     │        │                              │          │
└──────────────┴────────┴──────────────────────────────┴──────────┘
   offset 0-5      6            7 … N-2                     N-1
```

- **Length（offset 6）**：整帧总字节数，含帧头、Length 自身、用户数据区、帧 CheckSum。
- **用户数据区**：`Command(1) + UD Length(1) + Data(0..N) + 用户数据 CheckSum(1)`。
- **双层校验（SUM8，低 8 位累加和）**：
  - 内层 `[UDSUM]`：仅对**用户数据区**字节（固定从 offset 7 起，到内层 CheckSum 前一个字节）累加取低 8 位。
  - 外层 `[SUM]`：对**帧头到内层 CheckSum（含）的全部字节**累加取低 8 位，位于帧尾。
- 规则文件中发送帧用占位符 `[UDSUM]`、`[SUM]`，运行时由 `ChecksumEncoder` 自动计算，**禁止手工填校验字节**。

### 1.1 校验手算示例（亮度 50% 帧）

发送帧：`53 57 49 4F 54 54 0C 18 04 32 4E 92`

- 用户数据区（offset 7–10）：`18 04 32`
  - 内层和 = 0x18+0x04+0x32 = 0x4E → offset 10 字节 = `4E` ✓
- 外层和 = 0x53+0x57+0x49+0x4F+0x54+0x54+0x0C+0x18+0x04+0x32+0x4E = 0x192 → 低 8 位 = `92` ✓

## 2. 字节序与字段解析规则

| 规则 | 结论 | 依据 |
|---|---|---|
| 多字节数值字节序 | **小端 little-endian** | D8 帧 `B6 00`=0x00B6=182→18.2V；`00 32`=0x3200=12800mA；`04 06`=0x0604=1540→154.0W |
| 单字节 | 无字节序问题 | 枚举/位掩码直接取整 |
| 工程值换算 | `display = raw × scale` | 电压 0.1、功率 0.1、电流 1、百分比 1 |
| 位掩码 | 先取整再 `& bitMask` | 故障字节、充放电状态(bit7)、容量(bit0–6) |
| 枚举 | 按协议 EnumMap 映射 | 工作模式、DI 电平、充放电状态 |
| 有符号 | 仅 i8 按有符号解析 | 倾斜角等 |
| 帧过滤 | 先匹配 frameFilter 再解析 | 防止查询回环/其他命令帧污染字段值 |

## 3. 标准解析 SOP（每帧严格执行，任一步失败即中止并按"失败处理"执行）

### 步骤 1　帧头校验
- 检查前 6 字节是否为 `53 57 49 4F 54 54`。
- **失败处理**：丢弃字节流并重新同步帧头；记日志，不进入后续步骤。

### 步骤 2　Length 校验与组帧
- 读 offset 6 的 Length，确认 `Length ≥ 8`（最小帧：6 头 + 1 长度 + 命令 + 内层和 + 外层和）。
- 按 Length 收齐整帧；数据不足时由 `StreamFramer` 保留残帧等待后续字节，**禁止对残帧解析**。
- 与权威长度表（见附录 A）核对，长度不符直接判坏帧。
- **失败处理**：坏帧丢弃、记日志，不影响连接与下一帧。

### 步骤 3　双层 SUM8 校验
- 重算内层 `[UDSUM]`，与帧中内层 CheckSum 字节比对。
- 重算外层 `[SUM]`，与帧尾字节比对。
- **失败处理**：任一不符即判校验失败，丢弃该帧并记日志，不更新任何字段（防止脏数据落盘）。

### 步骤 4　frameFilter 隔离
- 按命令码（offset 7）匹配对应 charts/fields 的 frameFilter（通配 `??` 忽略可变字节）。
- 只有匹配成功的规则项才参与解析，避免无关帧（如查询回环、其他功能码）串值。
- **失败处理**：无匹配项时仅留原始日志，不更新字段。

### 步骤 5　字段解析
- 按每项 `offset / length / dataType / endian / bitMask / scale / enumMap` 解析。
- 多字节一律小端；先位掩码、再缩放；u32 长度不足 4 字节返回 0，不抛异常。
- 结果写入 `ParsedValues[key]`，并回填字段区 `FieldRows`。

### 步骤 6　产线过站存表（操作员点"保存本台记录"）
- 校验已读到设备码（D7），未读到则拒绝保存并提示。
- 自动截取主窗口 PNG，存 `Data/Production/images/`。
- 按设备码追加一条汇总到该设备 CSV（首次自动建表头、UTF-8 BOM）。
- 截图列写 HYPERLINK 相对路径；截图失败不阻断存表，仅截图列留空。

### 步骤 7　即插即用与数据携带
- 数据全部位于 exe 同级 `Data/Production/`，不写 C 盘。
- 整个程序文件夹（含 Data）拷到产线任一电脑或 U 盘，历史记录与截图随程序走。
- 设备标识用设备上报的设备码，更换 COM 口不影响归到同一台设备。

### 异常隔离总原则
- 单帧解析、自动应答、文件 IO 全部 try/catch 隔离，异常只记日志，不终止连接、不影响其他帧。

## 4. 产线存表说明（回答"读取之后能不能存参数"）

- **定位**：用于产线生产、即插即用，不写 C 盘；解析值在内存中实时更新，测完由操作员点"保存本台记录"追加落表。
- **全局只有一张表**：无论插拔多少次、多少台设备，都追加到同一个 `生产记录.csv`，设备码作为一列区分。
- **存储位置（exe 同级，随程序走）**：
  ```
  <程序目录>/Data/Production/
    ├─ 生产记录.csv             全局唯一数据表，所有记录逐行追加
    └─ images/设备<码>_<时间>.png  自动截主窗口
  ```
- **表结构**：固定前置列 `时间 / 设备码 / 端口`，随后按规则 fields+charts 顺序排列全部参数列，末列 `截图` 为 `=HYPERLINK("images/xxx.png","查看截图")`，Excel 点击即看图。
- **追加与防错列**：已存在文件按磁盘表头对齐写入；规则版本变化也不会错列；UTF-8 BOM，Excel 中文不乱码。
- **界面展示**：「参数配置 → 测试数据表」Tab 内 GridControl 绑定该 CSV，保存后自动刷新；「测试页」Tab 为承载独立测试页面的容器。
- **相关代码**：
  - `Services/Production/ProductionRecordService.cs`（全局单表追加、表头对齐、HYPERLINK、RecordAppended 事件）
  - `Services/Production/WindowCaptureService.cs`（主窗口自动截图，含 DPI）
  - `ViewModels/DevicePanelViewModel.cs`（CSV 读取到 DataTable，自动刷新）
  - `Views/DevicePanelView.xaml`（测试页容器 + 数据表 GridControl）
  - `Protocols/Serial/ViewModels/SerialViewModel.cs`（OnRecordSaveRequested 串联校验/截图/存表）

## 5. 测试样例（HEX 帧 + 预期解析，均已实测校验通过）

### 样例 1　设置 LED 亮度 50%（命令 18，应答 98）
- TX：`53 57 49 4F 54 54 0C 18 04 32 4E 92`
- RX：`53 57 49 4F 54 54 0C 98 04 32 CE 92`
- 预期：`dim_level = 50%`，断言 PASS。

### 样例 2　关灯 0%
- TX：`53 57 49 4F 54 54 0C 18 04 00 1C 2E`
- 预期：`dim_level = 0%`。

### 样例 3　组播 1 组 50%（命令 19，无应答）
- TX：`53 57 49 4F 54 54 0D 19 05 01 32 51 99`
- 预期：单向帧，无应答。

### 样例 4　远程重启（38 → B8）
- TX：`53 57 49 4F 54 54 0C 38 04 01 3D 70`
- RX：`53 57 49 4F 54 54 0C B8 04 01 BD 70`
- 预期：重启应答，断言 PASS。

### 样例 5　光伏数据（D8，小端）
- RX：`53 57 49 4F 54 54 11 D8 09 B6 00 00 32 04 06 D3 A1`
- 预期解析：
  - 光伏电压 = 0x00B6 × 0.1 = **18.2 V**
  - 充电电流 = 0x3200 = **12800 mA**
  - 充电功率 = 0x0604 × 0.1 = **154.0 W**

### 样例 6　电池数据（D9，小端）
- RX：`53 57 49 4F 54 54 12 D9 0A 80 00 50 46 00 09 50 52 00 A0`
- 预期解析：
  - 电池电压 = 0x0080 × 0.1 = **12.8 V**
  - 电池电流 = 0x4650 = **18000 mA**
  - 电池功率 = 0x0900 × 0.1 = **230.4 W**
  - 状态字节 bit7 = 0 → **放电**；bit0–6 = 0x50 → **容量 80%**
  - RSSI 字节 = 0x52 = 82（文档文字称 0，见第 7 节笔误）

### 样例 7　能耗数据（D6，u32 小端）
- RX：`53 57 49 4F 54 54 13 D6 0B 10 27 00 00 AC 26 00 00 EA D1`
- 预期：累计发电 = 0x00002710 = **10000 Wh**；累计耗电 = 0x000026AC = **9900 Wh**。

### 样例 8　LED 数据（DA，小端）
- RX：`53 57 49 4F 54 54 12 DA 0A 68 01 B8 0B 38 04 50 9C 34`
- 预期：LED 电压 = 0x0168×0.1 = **36.0 V**；电流 = 0x0BB8 = **3000 mA**；功率 = 0x0438×0.1 = **108.0 W**；调光 = **80%**。

### 样例 9　时序调光文件查询（6F，三帧，全 FF）
- 帧 1：`53 57 49 4F 54 54 13 6F 00 FF FF FF FF FF FF FF FF FF 63`
- 帧 2：`53 57 49 4F 54 54 13 6F 01 FF FF FF FF FF FF FF FF FF 64`
- 帧 3：`53 57 49 4F 54 54 11 6F 02 FF FF FF FF FF FF 38 9E`
- 说明：跨帧整体校验，Check 仅在第 3 帧；全 FF 表示未配置。

## 6. 回环测试步骤（真实/虚拟串口，不用模拟器软件）

1. 用虚拟串口驱动（如 VSPD）建立成对端口 COM A / COM B；或用真实 USB-485 对连。
2. 本程序开两个实例：实例 1 打开 COM A，实例 2 打开 COM B；设备类型均选「SCx太阳能控制器」，实例 2 勾选自动应答（autoReplies）。
3. 串口参数按实机设置（协议未定义，常用 9600 / 8 / N / 1）。
4. 实例 1 点 quickSend「设置LED亮度50%」：
   - 核对 TX 区字节与样例 1 完全一致；
   - 实例 2 自动回 98 帧，实例 1 断言 PASS、字段面板显示 50%。
5. 依次点「查询光伏/电池/能耗/LED」，并先执行固定参数查询（D7）读到设备码，对照第 5 节预期值逐字段核对。
6. 存表验证（产线过站）：
   - 点「保存本台记录」，确认在 `Data/Production/生产记录.csv` 追加一行，且 `images/` 下出现主窗口 PNG；
   - 用 Excel 打开 CSV，核对各参数列与预期一致，点截图列 HYPERLINK 能打开图片；
   - 插拔换口、换另一台设备再保存，确认都写进同一个 CSV、表头不重复、不错列；
   - 切到「测试数据表」Tab，GridControl 应自动显示含最新行的同一张表。
7. 即插即用验证：把整个程序文件夹拷到另一台电脑（或 U 盘）运行，确认 Data/Production 历史与截图随程序可见。
8. 反向验证：实例 2 手动发送样例帧，实例 1 字段面板刷新；再发一条错误校验帧，确认被丢弃且原字段值不变。
9. 异常验证：未读到设备码时点保存应被拒绝并提示；发送帧头错误/长度不足/校验错误帧各一条，确认均被隔离、连接不断、日志有记录。

## 7. 已知文档笔误与限制（解析时以规则文件为准）

1. D7、D9 示例帧的校验字节/长度与 SUM8 规则不符，规则文件用占位符运行时自动计算正确值，规避笔误。
2. D9 文档帧实际 19 字节而 Length 写 0x12（18），存在矛盾；frameFilter 按文档示例帧实际字节匹配。
3. GPS 文档文字称 RSSI=0，但帧中字节为 0x52（82），以字节为准。
4. GPS 经纬度协议为 8 字节 double，当前解析器仅支持 float32，精度受限；如需高精度需扩展 float64 类型。
5. 6F 三帧为跨帧整体校验，仅第 3 帧带 Check，已用固定帧处理。
6. 波特率/校验位等串口参数协议未给出，需按实机确认，当前按 9600/8/N/1 假设。
